# Agent Note: P10 针对 RT-01 的网表验收

Status: implemented

[English](2026-09-27-p10-netlist-acceptance.md) | 中文

## Problem

RTL 仿真可以执行由 metacomment 向综合隐藏的逻辑。因此，即使 RTL 仿真通过，综合进程成功也不能证明硬件行为正确。RT-01 展示了导线评测通过、综合网表却输出恒零的 DUT。

## Decision

[候选策略](../../../../rtl-tools/src/phase1/p09-auto-policy.ts) 在删除注释前拒绝综合控制 metacomment，包括裸 `translate_off/on` 及 `synthesis`、`synopsys`、`pragma` 或 `xilinx` 前缀，保留提交字节及源码位置。生成纠正和拒绝工具动作沿用既有上限；被拒绝源码不计接受编辑，也不启动 EDA。

[P10 检查器](../../../../rtl-tools/src/phase1/p10-netlist.ts) 新增版本化验收收据，不改变四阶段持久化 schema。它绑定原封存 run、源码、网表、Host 持有的 oracle、库及进程证据。精确题面规则要求已校准的 Windows Vivado 2025.2 库；[题库校准决策](../testing/2026-09-27-p10-netlist-suite.zh.md) 负责导线、非门和同步复位 DFF8 公开规格对照之外的覆盖范围。显式 GSR 启动条件、case-inequality 比较及固定正检查数阻止断言位上的 DUT 未知值或空仿真获得成功。

同一收据授权 Baseline、Agent、导出及报告。失配以设计验证失败终止，不意味着网表修复机会已经耗尽。不支持的身份拒绝验收，不丢弃题目。[移植决策](2026-09-18-p10-reviewed-compatibility.zh.md) 仍拥有评测器派生规则；本决策取代“四阶段成功足以授权 P10 导出”，不取代适配器或历史收据。

## Alternatives considered

**删除指令或禁止全部初始化。** 删除会改变被评分的候选。全面禁止初始化会拒绝合法 FPGA 设计，也不能解决所有语义分裂机制。

**只拒绝已知指令。** 这能封堵已证明的攻击入口，却不能证明综合行为，仍需独立网表检查。

**立即增加共享第五阶段或形式等价。** 二者都会扩大无关的历史协议及工具范围。P10 收据保持本次修复聚焦；明确承认有限 oracle 覆盖弱于等价证明。

**不经校准复用全部 testbench。** GSR 和启动时序可能使 RTL 阶段的假设失效。精确题面 profile 与固定库牺牲覆盖范围，换取可审计的验收标准。

## Consequences

聚焦测试覆盖全部候选入口、不变的编辑预算、网表错误分类、过期网表、库身份、被改收据及成功证据缺失。真实工具校准及日志保存在外部 RT-01 验证批次，不属于模型成绩。历史候选只读扫描，不改写历史结果。

初始化校准不授权任意时序题，每项启用规则都需要自己的证据。验收增加独立记录且有界的 EDA 成本，模型及修复预算不变。RT-02、隐藏测试正确性、完整 OS 隔离及形式 RTL/网表等价仍未解决。新运行与旧四阶段结果使用不同实验标准。
