# Agent Note: Repair Eligibility, Bounded Stream Audit and Provider Accounting

Status: implemented

English | [中文](2026-10-09-p3-production-continuity.zh.md)

## Problem

Repair proposals need current DUT evidence without treating conservative parser flags as execution authority. Stream consumers also need a bounded public audit without losing complete archives or confusing semantic rejection with transport completion and provider usage. These decisions affect different facts and must remain independently observable.

## Decision

[Repair policy](../../../../rtl-tools/src/phase1/repair-policy.ts) and revision comparison share one pure predicate for complete, normally executed DUT `VRFC 10-3818` elaboration failures. The predicate requires exact conflict text, a nonempty invocation, explicit DUT attribution and an independent current DUT source binding. [Diagnostic loading](../../../../rtl-tools/src/phase1/repair-diagnostics.ts) establishes that binding only when the manifest's listed file hashes are verified, its unique DUT matches the recorded final source hash, and actual DUT inputs of non-version compile invocations are present and all match that source. The predicate resolves each primary diagnostic's current file against the bound working directory and compares its normalized path again with the bound DUT path. Missing or inconsistent binding and stale DUT attribution labels cannot grant eligibility. It admits only exact unlocated `XSIM 43-3322` summaries bound to a qualifying conflict's invocation. Raw `repairable_by_model` stays false; a rejected driver case cannot fall through to generic eligibility. Proposal approval and source execution remain separate responsibilities.

[StreamAudit](../../../../rtl-tools/src/phase1/stream-audit.ts) maintains a bounded public projection incrementally. The managed action writer publishes its `chunks` and metadata in `stream-audit.json`; full received normalized archives remain in `stream.json` and `stream.jsonl`. Exact compact-array UTF-8 accounting includes brackets, commas and escapes. Actions use `maxEventBytes / 2` without rounding and reserve 4096 bytes for usage and finish. Ordinary overflow closes the retained ordinary prefix and omits whole chunks without holding their payloads. Critical overflow records `AUDIT_METADATA_LIMIT`, false `terminal_metadata_preserved` and omission counts; it does not create semantic `OUTPUT_TRUNCATED`. The archive and projection reuse the same finish-error normalization.

[Provider accounting](../../../../rtl-tools/src/phase1/provider-usage.ts) validates observed normalized counts independently of accepted content. It reports returned, missing-provider, incomplete-host or unparseable usage, with unavailable counts null. Incomplete host observation does not prove that the provider sent unread counters. Input and disjoint cache buckets contribute once to prompt counts; reasoning remains part of output. Safe nonnegative integers and an exact provided total are required, including valid zero. Identical normalized samples are not accumulated; conflicts and invalid samples remain explicit. Telemetry records sample provenance and actual iterator exhaustion; valid received usage survives later interruption. These additive public observation fields retain the existing record schemas and do not classify historical records retrospectively.

The [DeepSeek translator](../../../../packages/llm/llm-deepseek/src/translate.ts) sets optional `providerProtocolComplete=true` only after actual `[DONE]` and any preceding accounting. Telemetry retains this independent fact in public `provider_protocol_complete` and `provider_protocol_completion_source`; the latter is `normalized-provider-stream-marker` when the marker is observed. Error code and normal Runtime iterator exhaustion cannot distinguish a completed empty provider response from a locally synthesized no-body `EMPTY_RESPONSE`. The explicit marker permits missing-provider classification for a completed provider error without usage; an unmarked local error remains incomplete-host. Marker absence supplies no proof of protocol completion, and semantic rejection or later cancellation does not erase an observed completion or valid usage. Sanitized archives and the bounded audit retain only the permitted marker beside existing finish fields; request selection, retries and all budgets remain unchanged.

[Action draining](../../../../rtl-tools/src/phase1/p09-action-call.ts) uses one iterator for archives, audit, telemetry and semantic assembly. First semantic byte overflow locks `OUTPUT_TRUNCATED` and a null message, stops assembly and continues metadata observation with the original controller, signal and timer. Content finish does not establish EOF. Later transport or provider errors cannot replace that first semantic error; independent terminal and persistence facts remain visible. The provider must settle pending reads on the original signal. Authentication, safety and user cancellation retain immediate termination. The drain adds no grace, dispatch, retry or detached reader.

## Alternatives considered

**Grant eligibility from a raw flag or broad diagnostic kind.** Rejected because it lets incomplete, misattributed or differently invoked errors grant repair authority. The pure predicate preserves conservative parsing and enforces current evidence in both policy and revision ranking.

**Trim complete archives or buffer all audit payloads until finish.** Rejected because trimming loses evidence and deferred trimming makes projection memory unbounded. Whole-chunk incremental omission retains only permitted public payloads and identifies missing critical metadata explicitly.

**Estimate usage, substitute zero or sum repeated samples.** Rejected because these operations invent provider accounting or count one call more than once. Classification describes only samples observed at the normalized provider interface.

**Stop at semantic overflow or start a fresh metadata window.** Rejected because immediate stopping can lose terminal usage, while a new window changes the request budget. One cancellable iterator preserves the semantic limit and observes metadata within the original deadline.

## Consequences

Readers use the independent audit file when they need bounded chunks and its omission metadata when deciding completeness. Full archives retain all received normalized chunks and their existing storage costs; the projection does not claim bounded whole-call memory. Audit failure, semantic failure, transport failure and accounting availability can coexist. A content finish alone cannot justify missing-provider classification, and provider cancellation behavior remains necessary for bounded pending-read settlement. The [Phase 1 README](../../../../rtl-tools/phase1/README.md) owns consumer guidance; existing repair approval, time budgets, Job/Scope ownership, Skill defaults and G2 criteria are unchanged.
