# Agent Note: P10 有界候选恢复与独立修复预算

Status: implemented

[English](2026-09-23-p10-candidate-budget.md) | 中文

## 问题

仅 reasoning 的截断、部分传输及被拒绝的完整 RTL 过去会终止候选获取。三次修改及旧请求/工具上限也无法容纳用户要求的十五次已验证修改。全题库还包含不规范公开接口及评测器故障，不能将它们算作模型错误。

## 决策

[Repair-v4](../../../../rtl-tools/phase1/p10/README.zh.md#repair-v4-and-all-task-campaigns) 允许两次有日志的关闭思考候选纠正，使用之前返回的文本及 Host 拒绝原因，不使用参考答案或评测反馈。十五次接受的修改、六十个工具动作、120 次修复尝试及显式授权的全局调用上限分别计数。所有重试共用有限请求账本。禁用生成续跑及探测后，156 题上界保持为 20124 次。全局默认授权仍为 375。

## 考虑过的替代方案

**无限重试或悄悄选择后续成功样本。** 这会隐藏失败且使费用失控。所有被拒绝的尝试都保留，首个合法候选获取与严格 pass@1 分开报告。

**只提高修改次数。** 旧请求和工具限制仍会提前阻止十五个完整的修改/验证周期。独立计数及调用前校验避免误导性配置。

**使用参考端口修补歧义题。** 这会改变公开题目并泄露评测知识。题面冲突保持明确排除；无歧义的标点及内嵌声明由本地解析支持。

## 后果

授权预算增大可能增加费用和时间，不保证 RTL 必定合法或正确。候选恢复改变采样协议，跨批次差异不能只归因于修改次数。校准计分、完整证据、回滚及通过导出门控不变。旧记录永不覆盖。

## 测试

聚焦测试覆盖两次纠正终止、部分输出恢复、关闭思考参数、首尾空白拒绝、含强制动作重试的十五个完整修改/验证周期、独立工具/请求限制、显式 156 题权限、全局上限校验及阻塞题分母。真实模型行为及十分钟综合仅在独立冻结的授权批次中测量。
