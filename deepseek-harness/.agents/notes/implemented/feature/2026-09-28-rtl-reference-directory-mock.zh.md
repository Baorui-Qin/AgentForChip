# Agent Note: RTL 参考目录 mock

Status: implemented

[English](2026-09-28-rtl-reference-directory-mock.md) | 中文

## 问题

P10 的已登记任务、campaign 及依赖评测器的研究不能证明只有题面的目录接口兼容性。复用共享初始候选也不能证明独立参考基线。接口验证需要不暗示模型能力、不改变研究验收的证据。

## 决策

[目录适配器](../../../../rtl-tools/reference/README.zh.md)是独立 dsh profile，配置必须显式选择 mock。它解析公开参考项目列表格式，生成带标记的零输出接口 fixture（测试前置数据），并分别记录空答案、错误、超时和取消。它不挂载 LLM（大语言模型）、EDA、凭证或研究插件。每个被接受的输出目录有排他占用标记和独立工作目录；重复调用需要新目标目录。

## 考虑过的替代方案

**复用 P10 命令。** 其输入身份和可信评测器依赖会保留待验证的不兼容性，并可能混淆研究验收与外部计分。

**复制参考答案或实现示例算法。** 两者都会让冒烟成功产物看起来像解题能力。只有接口的 mock 刻意不提供实际功能行为。

**启动独立 Node CLI。** 这会绕过仓库的 profile 启动要求。Shell 和 PowerShell 包装脚本改为选择 dsh。

## 影响

现有 P10 命令及严格最终验收保持不变。不暗示已具备生产解题器或可移植提交包。解析器拒绝不支持的语法，而不猜测缺失端口。原版基线文件保持外部冻结依赖身份，不改写为 P10 对照路径。

## 测试

所有者目录中的测试固定无密钥产物快照、新目录占用、显式结果及取消后等待结束的行为。此处不存在可录入会话快照目录的 Session。真实 dsh 调用验证源码启动路径。Linux 信号、包含进程启动的总时限、真实模型服务兼容性及操作系统强制裁判隔离均需独立验证；此 mock 不提供这些证据。
