# Agent Note: 有界 RTL 验证事实

Status: implemented

[English](2026-09-13-rtl-simulation-tool.md) | 中文

## 问题

RTL 修复需要真实的编译器和仿真证据，同时不能让原始日志充斥模型上下文。进程成功本身不能证明测试台通过；第一个开发工具也不应修改 agent loop（智能体循环），或冒充正式比赛评分器。

## 决策

可选的 [rtl-tools 插件](../../../../rtl-tools/README.zh.md) 注册 `run_simulation`，使用配置指定的一个可信顶层模块和源文件列表。它使用既有 subprocess 和 sandbox 服务。运行器先编译再仿真，在内存和磁盘上限内流式处理诊断，保留每次调用的私有产物，传递取消信号，并在返回前等待受管进程范围退出。解析器报告观察到的错误和位置，不修复 RTL，也不推断诊断之间的因果关系。

PASS 要求运行结果正常、观察到配置的整行测试台标记，并且诊断行未被截断。缺乏证据时返回 UNCONFIRMED。测试台标记不是权威评分器，无法抵御候选代码伪造输出。只读评分资产和外部评分仍由部署方负责。

可选综合配置注册 `run_synthesis`，独立指定设计源文件、顶层和可信 XDC 文件。两个工具共享有界流式采集与进程所有权，不共享后端专用诊断和判定逻辑。Vivado 先导出网表和 checkpoint，再由独立批处理调用打开 checkpoint 生成报告。这让报告失败时仍可保留已确认的可综合事实，代价是额外启动一次 Vivado。报告提供 Used 列的资源计数和综合后 WNS；未知值为 null，不伪造零值。正 WNS 不是完整时序判定，负 WNS 也不否定可综合性。

[第一阶段开发应用](../../../../rtl-tools/phase1/README.zh.md) 将项目记录保持在已发布的 Harness Session 数据之外。模型记录使用 1.1，验证器记录使用 1.3，读取器保留 1.0/1.1 支持。dsh doctor 记录观察到的环境事实，并拒绝自动降级为无隔离执行。独立的 Windows 夹具应用依次执行编译、展开、仿真与综合；宿主发放的快照标识绑定固定资产与哈希。只有明确的非 Agent、一次性冒烟许可允许完整访问。普通调用要求完整沙箱保护。哈希检查可以检测但不能阻止篡改，因此完整操作系统隔离仍是独立要求。

官方 API 应用复用已准备调用与既有凭据提供方，不创建另一套 HTTP 客户端或本地推理服务。它将流式响应聚合为有界文本，记录实际提示词与解析后的请求设置，不提供工具，也不执行返回代码。项目尝试计数不声称测量 HTTP 送达。取消释放客户端流，但不宣称云端生成已终止。十次顺序尝试保留失败，不通过重新采样获得通过的验收结果。

单题 counter 开发应用将生成与宿主审查、执行分开。显式源码摘要仅授权一份已保存响应使用不变的评分资产；磁盘认领文件阻止再次验证同一生成。`reviewed_candidate` 信任标记区分已检查的模型输出与手写夹具。此狭窄的宿主专用路径使真实反馈可以被观察，又不会授予模型通用的完整访问许可。第二次只读调用接收精简事实，但不能执行修复。普通夹具工具和纯 API 冒烟测试保留原有授权边界。

[三路线对照](../../../../rtl-tools/phase1/comparison/README.zh.md) 将真正的 Baseline 进程与 Agent、EDA 服务隔离。其冻结的 VerilogEval 提示与 Agent-Base 生成完全一致；Agent-Domain 仅增加上游规则。宿主评分独立于生成，一次只读解读不能修复或改善该候选。严格的子串提取以及排他、哈希绑定的版本、审批和导出记录，阻止暗中修正答案或冒用旧 PASS。实验信封使用 1.2，与原生记录版本独立。原始评分器预检在不兼容时阻止真实生成，不静默移植基准。

[Vivado 语言解析](../../../../rtl-tools/phase1/language/README.zh.md) 由编译与综合共享，因为只按文件名推断可能偏离任务意图。显式冲突在执行前失败；连续分组保留顺序和统一阶段截止时间，不重新排序库。源文件角色和有效模式进入快照与评分哈希。精确清单归属区分 DUT 错误和可信评分器兼容性，不声称推断了根因。不完整或混合诊断不能授权模型修复。版本探测退出码 1 保留为观察事实，只有横幅匹配且正常终止才接受，不改写成零。不会通过重写基准源码或语言降级掩盖兼容性失败。

## 考虑过的替代方案

可选的 [P09 上下文路径](../../../../rtl-tools/phase1/p09/README.zh.md) 保留在人工审查工作流内部，不增加第二个修复循环。当前源码与独立失败事实属于必需内容，历史观察转为短事实账本。这以可能损失历史细节为代价，获得有界且可重建的请求，无需额外总结调用。运行时使用固定的官方 recipe 计量，否则拒绝计数；Mock 估算仅证明控制流程。独立恢复计数不能绕过总尝试上限、审查或重新验证。五个内部任务将公开题面与私有校准资产分离，自然首次生成请求不继承注入缺陷的答案。

实际观察到的 Vivado 2025.2 汇总值 WNS=inf、TNS=0.000 使用明确的 non_finite_wns 结果，松弛值为 null 并保留警告。这避免将已识别的报告值当作损坏，同时不宣称存在有限建立时间松弛、缺失约束或实现时序收敛。其他非法拼写仍返回报告错误。

**在插件中直接使用 child_process。** 这会重复既有的凭据清理和进程范围清理，并可能绕过文件隔离配置。因此插件使用已有服务。

**返回完整 stdout 或仅返回末尾日志。** 完整日志消耗上下文，末尾日志会丢失早期编译错误。流式解析保留有界的首批诊断，同时单独保留有上限的原始日志和明确的截断事实。

**将退出码零视为功能 PASS。** 测试台可以在没有检查设计的情况下结束，因此缺乏明确通过证据不等于成功。

**将所有未通过的判据归为 Harness 配置错误。** 即使仿真器退出码为零，完整判据中的非零失配仍确定功能失败。诊断保留计数，不编造失败位置，也不授予修复资格；格式错误或冲突证据保持不确定。这区分观察到的失败与根因推断，并保留负例作为回归证据。

**先建立多后端工作区包。** 本地源码插件避免修改已发布的组合配置和工作区元数据。综合仍按需启用；独立的 Vivado 夹具应用不替代 Icarus 行为。

**从综合 INFO 消息推测资源，或把所有结果合并为一个布尔值。** INFO 消息不是资源报告，且可能描述中间设计。独立的报告解析和可空综合证据可以区分不支持的报告格式、环境故障与 RTL 错误。解析器针对 Vivado 2025.2 文本表格，不假装该版本具有后续版本的 JSON 选项。

## 影响

[人工审查分离的 counter 修复应用](../../../../rtl-tools/phase1/repair/README.zh.md)在事实和提案之间增加宿主策略，不把策略写入解析器。完整且已校准的功能失配可以在源码位置未知时支持修复提案；独立的一次性人工审批控制候选执行。历史诊断重解析明确不具有此资格。固定负例仍为回归资产，每次模型响应产生新版本。默认两次提案协议不重试。显式启用的有限循环将最多三轮语义修复与每轮两次传输重试分开；收到任何响应字节后拒绝重试。Schema 1.5 事件绑定提示和配置哈希、当前源码反馈，以及重复候选和重复诊断终止条件。受控分阶段缺陷夹具检验状态机，不代表自然 benchmark 表现。派发前持久化状态防止重发结果不明的操作。随附 profile 在单独授权前拒绝 EDA 执行，不开启广泛的持久完整访问。

独立工具不新增本地模型后端、重试循环、RTL 修复或数据集测试台修改。EDA 执行使用同一主机上的文件和进程。可信 Windows 批处理参数拒绝 shell 元字符，并由进程提供方负责 argv 转义；Tcl 值单独转义。宿主验证序列要求此前仿真通过，独立综合工具没有此要求。轮询产物审计会停止观察到的超限，但不是操作系统磁盘配额。完整访问的夹具和已审查候选工作流不能证明对恶意 HDL 的保护或正式比赛就绪。单题路线差异不能证明统计显著性或 Agent 正确率增益。

定向测试覆盖 Loader 注册、独立工具的真实 agent-loop Session 记录、项目事件还原、schema 校验、受管进程清理、失败短路、哈希检查、取消、插件卸载与有界快照。API Mock 测试覆盖完整流、协议错误、凭据、服务故障、超时和取消。真实 Vivado 夹具与官方 API 尝试具有独立的 dsh 产物，不作为 Mock 证据。Linux Vivado、布线后时序、本地模型及 ROCm、对抗性操作系统隔离均未由这些组件证明。
