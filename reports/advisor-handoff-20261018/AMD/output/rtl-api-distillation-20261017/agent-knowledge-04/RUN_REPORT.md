## 运行前控制修复

- 分题请求、token、EDA 配额与外发前守卫统一读取计划，互不挪用。未知接收或用量不按零处理。
- 原样写回计数不再被普通读文件或评测操作清零；三次原样写回会阻止下一模型步骤。新内容 hash 本身仍不证明有效进展。
- 总结接收后拒绝同批排队操作，避免已绑定证据被随后写入改变。
- 保留公开诊断失败打印、显式失败与 watchdog，不能用 done/PASS 覆盖失败；修改与最终验证事实由操作 ID、hash 和真实结果生成。
- 真实测试台预检：修正 Q114/Q193 的源端保持、沿前握手、沿后状态采样和计数；相同合规测试能拒绝原始错误并检查旧候选。这些只算开发者回归，不算本轮模型修复。

运行前 23 项 Python 工具/预算单测、14 项检索测试、10 项原生 Harness 控制测试通过；7 次真实 EDA 回归包括协议正负候选和诊断假通过负例。预检没有向后续模型提供修好的 DUT 或测试台。

## 关键纠错证据

### Q123：仍未修复，新增明确的容量反证

模型在修改前收到了 R-CDC、T-001、T-002，但只做了删除重复声明的语法修复，二进制指针仍缺回绕位，Gray 也不是完整指针的转换。模型测试台还串行写入超过容量的数据而不启动读取，这类 watchdog 不足以单独归因于 DUT。

开发者另用无读端流量、允许同步稳定、沿前稳定驱动及有界等待的容量检查，在**同一最终 DUT** 上观察到第三笔写入无法接受。该反证与模型 watchdog 分开记录：[容量诊断](independent-diagnostics/Q123/operations/001/result.json)。不能用冻结通过覆盖它。

### Q155：真实修复成功，但总结仍须纠正

实际修改使用 signed 商、非负余数、数值 0/+1 的增量，并在舍入后饱和。首次测试台因 `expect` 保留字编译失败，模型真实改写后重跑通过。模型自写诊断覆盖 23 个定向输入；开发者另使用绝对值/商余数算法做全输入穷举，未复制 DUT 的位切片参考逻辑：[独立穷举结果](independent-diagnostics/Q155/operations/001/result.json)。

原总结错误地声称旧代码“饱和发生在截断后”，并把半值行为概括为全部远离零。旧代码根本没有饱和逻辑，正偏置也不等于该带符号半值规则。原总结不覆盖，审查单独纠正。这说明操作绑定解决不了自由诊断叙述的全部失真。

### Q193 / Q114：RTL 与测试台责任分开

Q193 的本轮 DUT 实际改为各分支独立 pending，但模型测试仍在活动沿驱动/检查，并在 valid 持续为高时漏计额外接受机会。只把监视器赋值改为 NBA 并未修复整个时序和事务序列。最终冻结验证及合规测试由开发者补做，不能伪装成 API 工具调用。

Q114 新测试虽把复位释放移到下降沿，却在 A 接受后仍保持 valid 经过额外阻塞沿，形成新的 A 请求，随后将其改成 B。静态审查确认违反公共输入保持约定；“诊断通过”不能证明测试台合规。

已完成独立修正并实际运行的测试台：[Q114 合规测试台](independent-protocol-review/Q114/work/diag_tb.sv)、[Q193 合规测试台](independent-protocol-review/Q193/work/diag_tb.sv)、[补验结果与来源标签](independent-protocol-review/validation.json)。模型原测试和失败记录均未修改。

### Q083：最终验证补齐，不能回填成模型自主完成

模型在第三次入队后的已满状态检查 `s_ready==1`，混淆了接受沿前条件和沿后状态。宿主保留了 FAIL/FAILED/Fatal；之后提议写回的内容逐字相同，并未提出有效修正。该请求被收尾阶段写入守卫拒绝。

本轮最终源码已由模型请求完成三参数冻结验证，不借用上一轮结果。开发者独立测试改为沿前判定传输、沿后检查队列，同时覆盖满槽替换、连续回绕、阻塞保持、排空和复位：[模型冻结结果](tasks/Q083/operations/007/result.json)、[独立合规测试台](independent-fifo-review/Q083/work/diag_tb.sv)、[独立诊断结果](independent-fifo-review/validation.json)。没有伪造第八次请求或模型总结。
