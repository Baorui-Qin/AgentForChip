# Counter 修复开发

[English](README.md) | 中文

## 概述

修复应用分离诊断事实、宿主提案决策和人工执行审批。它使用固定注入的缺陷，不是自然生成错误。每例两次修复提案不证明无人干预修复、完整 OS 隔离或 Prob038 兼容性。固定负例保持不变。

## Profile 与命令

将 [rtl-repair profile](../profiles/rtl-repair/cordis.patch.yml) 的文件安装到独立的 `DSH_HOME/profiles/rtl-repair` 目录。仅通过 `dsh --profile rtl-repair` 启动；[PowerShell 包装](run.ps1)和 [shell 包装](run.sh)将命令转发给该启动器。随附 profile 使用 workspace-write，`allowReviewedFullAccess: false`。在宿主明确授权人工审查开发部署之前，真实 `start` 和 `resume` 拒绝执行。本文档不授予此权限，应用也不会从部分隔离自动降级为完整访问。

| 命令 | 结果 |
| --- | --- |
| `replay` | 读取宿主配置的 `replayRun`；另存诊断凭据，不调用 EDA 或模型 |
| `start functional` | 在已授权部署中校准正确 counter，验证新负例副本并请求修复提案 |
| `start syntax` / `start synthesis-only` | 使用相同评分器和提案限额的独立案例 |
| `status <experiment-id>` | 读取持久化状态，不派发任务 |
| `approve <experiment-id> <sha256>` | 为当前候选记录人工安全决定，不执行候选 |
| `reject <experiment-id> <sha256>` | 终止该例，保留全部证据 |
| `resume <experiment-id>` | 消费一次审批，用新快照从编译开始验证，随后终止或提出下一版本 |

Profile 补丁替换整个插件配置，不作局部合并。重解析只需要可读历史运行和可写产物目录。shell 包装只是薄启动器，不代表单独验收了 POSIX Vivado 部署。

## 事实、策略与审批

Schema 1.4 诊断凭据保留原结果、日志及资产哈希、解析器版本及源码摘要、进程事实、文件归属和症状类型。共享完成判据解析器保留失配计数，即使进程异常阻止修复。历史凭据使用 `evidence_kind=diagnostic_replay`、`eda_rerun=false`、`model_repair_executed=false`；宿主提案策略拒绝回放证据。原有 1.0/1.1/1.3 运行记录与 1.2 对照实验不重写。

`decideRepair` 接受已校准、版本绑定且完整的功能失配，不编造源码行号。DUT 编译错误要求识别到明确症状。综合缺失模块只允许观察到的 DUT 首要错误及同次调用中已识别的顶层、命令汇总。其他未知错误阻止提案。测试台归属本身不证明工具兼容性问题；声明顺序、依赖、语言模式和后继消息分别记录。提案决策不授予执行权限，也不修改旧 `repairable_by_model` 字段。

每次响应不作语义修正，提取为独占的新版本，绑定父版本、响应、源码、反馈及配置哈希。P05 保持 TopModule 接口；此流程从可信代码选择 counter 接口。模型只收到公开题意、当前源码与有界观察反馈，不收到评分器源码、参考答案或人工补丁解释。人工审查只检查执行安全，不编辑答案或按功能重新抽样。

编译阶段只有在同一文件、同一次调用存在已识别的 DUT 主错误，且 `VRFC 10-8530` 明确指向当前顶层时，才接纳该后继消息，不全局忽略它。真实验收暴露了最初遗漏的策略分支；原阻塞实验保持不变，另行授权的补充运行必须与它并列报告，不能替换原结果。

审批绑定完整候选标识且只能消费一次。资产或配置变化使续跑失效。每轮验证都在干净快照中从编译开始；导出读取当前已验证快照并复核哈希。另一种正确实现也可以通过：与手写答案文本相同不是判据。

## 预算与终止

默认 profile 每例最多两次 API 尝试和三轮候选验证，另有校准，不进行传输重试。显式开发默认值为 EDA 阶段 60/60/30/120 秒、每轮验证 300 秒、单次 API 请求 60 秒、每例活动操作时间 1200 秒。人工等待单独记录。模型默认配置为 `deepseek-flash`、temperature 0、输出 2048 tokens；实验内冻结实际解析的提供方、模型及推理配置。模型名称不代表固定了云端模型版本。不提供工具调用或额外解读请求。

已授权实验可以显式配置 `finiteLoop: true`：`maxSemanticRepairs: 3`、`maxTransportRetries: 2`、`transportBackoffMs: [1000, 2000]` 和 `maxRepeatedDiagnostic: 3`。每轮语义修复最多包含三次单独记录的传输尝试。只有已派发、未观察到任何正文或推理的连接、超时及 HTTP 502/503/504 错误允许重试。部分或完整答案、无效 RTL 及验证失败均不符合条件。每次重试绑定相同提示内容和解析后的生成配置；提供方消息标识元数据不属于提示内容。超时后云端请求可能继续，因此未收到字节不证明服务端没有工作或费用。

有限循环实验使用封装 schema 1.5，原生模型 1.1 和 EDA 1.3 记录不变。任意重复候选哈希、连续三次相同首要诊断、语义或活动预算耗尽、无效输出、审批拒绝及证据阻塞均会终止。`controlled_multi_round` 和 `controlled_multi_round_reset` 各含编译缺陷及独立功能缺陷；它们仅用于修复的 `state_machine_acceptance`，沿用未修改的 counter 评分资产。首次生成次数为零。最小修改提示只暴露当前证据，不提供潜在缺陷或补丁。一次修好时保留真实成功，绝不故意破坏输出以制造下一轮。

宿主在派发前持久化在途状态。并发命令加锁，中断操作不自动重复。死亡进程遗留的不完整或不一致锁及状态需要宿主调查。等待审批时不能续跑执行。取消和卸载等待受管活跃进程树退出。宿主突然终止不证明孤立 EDA 进程已退出；启动另一实验前检查残留进程仍是宿主职责。

独立终态覆盖修复通过、提案预算、活动或产物预算、源码无变化、无效输出、API 错误、审查拒绝、取消或中断、校准失败和证据阻塞。既有运行器继续执行进程和日志限制；操作后的实验大小检查属于检测，不是 OS 磁盘配额。设计成功与正确记录失败终态是两件事。

## 证据与验证

实验状态快照作为带编号的事件追加保存；原生模型事件保留完整请求与响应。各终态发布 `repair-result.json`、`repair-report.json` 及双语报告，包含阶段结果、版本哈希、可用 usage、模型和 EDA 时间及人工等待。未知价格与 TTFT 保持 null。中断或不完整证据可以产生 `report-incomplete.json`，不编造完整报告。

测试通过真实 Loader 和 Mock 服务覆盖提案、审查及续跑，以及两轮终止、源码绑定、重解析来源、声明顺序诊断、综合汇总识别和未知错误拒绝。已有 RTL、对照测试与真实模型证据分开。真实验收必须采用新的负例执行和实际经审查的模型候选；历史重解析与 Mock 成功不能替代。当前部署仍需要明确的宿主执行授权和逐候选人工审查。
