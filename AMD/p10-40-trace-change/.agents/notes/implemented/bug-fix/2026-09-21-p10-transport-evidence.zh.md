# Agent Note: P10 transport recovery and evidence

Status: implemented

[English](2026-09-21-p10-transport-evidence.md) | 中文

## 问题

调用 provider 不等于已观测到模型活动。网络原因丢失、批处理持续选取后续题目，可能在同一次故障期间耗尽多道题。分散的工具文件也难以区分 Host 评分、模型主动选择仿真，以及反馈是否进入后续请求。

## 决策

[P10 稳定性协议](../../../../rtl-tools/phase1/p10/README.zh.md#generation-stability-and-tool-evidence) 将 transport 遥测放在已发布模型记录之外，在 provider 规范化丢失 cause 前观测 Node fetch 诊断。不记录原始异常、请求头或端点 URL。只有规范化错误 finish 时，不能认定存在服务端活动。

生成窗口耗尽后暂停选题。恢复使用有界健康探针，只续跑原哈希及冻结配置下同一个零输出逻辑请求。各窗口终态不可变，仅更新最新结果指针。完整候选或部分输出不能借续跑重新采样。已有 Prompt、Skill 和修复策略保持不变。

工具轨迹关联真实进程记录、规范化诊断收据、渲染后的反馈及模型响应，分别报告 Host 初始验证和 Agent 工具验证。反馈消费表示绑定请求获得可观测响应，不声称了解模型内部推理。基础设施可靠性与候选可评测结果使用不同分母。

## 考虑过的替代方案

**无条件增加重试：** 在故障期间反复采样浪费预算，还可能隐藏 pass-at-k。有界同请求恢复保留全部失败物理尝试，并停止选取后续任务。

**修改共享 provider 失败 schema：** P10 需要传输证据，但不应为此修改已发布的 provider 或 session 格式。按调用隔离的 Node 诊断可在本地取得可用网络事实；其他传输方式允许保留不可用状态。

**增强反馈或更新修复策略：** 排查候选获取时改变模型输入会混淆归因。本次增加 Host 证据，不增加模型可见指导。

## 影响

增量规范化流旁路文件在解析及字节上限校验前保存 provider 返回的 reasoning、正文和工具增量。部分响应或被拒绝的响应仍可分析，不修改已发布 ModelRecord 数据或模型可见请求。文本提取文件仅便于阅读，有序流记录才是收到 chunk 的证据。未公开思考和含密钥的传输元数据不在归档范围内。

显式授权的四十题模式固定历史清单，合并经过哈希校验的校准记录。它采用新候选和有界 EDA 并发，不改变采样或修复策略。终态模型输出失败保留在固定样本中，基础设施耗尽仍停止选题。默认十题权限不会自动扩展。

保守断路器在首题重试耗尽后停止，不消耗后续题目。没有终态检查点的崩溃不能自动续跑。诊断通道仅适用于 Node fetch，缺失观测保持未知。复用校准必须显式冻结身份，新批次不能将旧模型候选混入成绩。

## 测试

定向测试覆盖规范化错误与 HTTP、模型活动的区分，并发隔离、敏感信息不落盘、相同哈希续跑、续跑上限、完整非法输出拒绝重采样、断路器和空修复分母。真实实验结果保存在仓库外，与模拟行为测试分别标识。
