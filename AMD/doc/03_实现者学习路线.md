# 03 · 作为实现者，你需要掌握哪些知识

## 1. 你的关键职责

你不必先成为大模型训练专家，但必须能判断“题目究竟要求什么”“测试是否可信”“报错来自模型还是环境”“新版本是否真的更好”。把代码交给 AI 后，这些责任不会自动消失。

最重要的能力是：**看懂一个小 RTL 电路、写出独立测试、用命令行把它验证完，并根据证据解释一次失败。**

## 2. 六类知识与可验收目标

| 知识 | 需要到什么程度 | 验收练习 |
|---|---|---|
| 数字电路 | 理解组合/时序、寄存器、时钟边沿、复位、状态机 | 不运行代码就能画出 10 个周期的计数器和 FSM 状态 |
| Verilog/SystemVerilog | 理解位宽、signed、阻塞/非阻塞、参数、数组、generate | 写出无意外锁存的组合逻辑和带边界测试的参数模块 |
| 仿真与验证 | 会写自检测试台、scoreboard、断言、读首个失败波形 | 主动注入 5 个错误，每个都能被测试捕捉 |
| Python/Linux/Tcl | 会组织模块、JSON、子进程、超时、日志、路径和命令行 | 一条命令完成编译、仿真、综合并输出机器可读结果 |
| 模型推理 | 理解权重、量化、KV cache、token、chat template、采样 | 本地离线服务运行，记录版本、峰值显存和吞吐 |
| 实验设计 | 理解基线、独立样本、消融、污染与可复現性 | 在固定任务集比较两版本，报告失败和置信程度 |

硬件语言和工具教程优先看 AMD UG900/UG901，HLS 看 UG1399 与官方入门例程；语法练习可用 HDLBits，但其在线判题不能代替赛事工具链。[R03][R04][R05][R15][R16]

## 3. 必須能解释的例子

### 非阻塞赋值不是普通逐句 Python 执行

```verilog
always_ff @(posedge clk) begin
    a <= b;
    b <= a;
end
```

这段在边沿后的结果是交换旧 a、旧 b。设计时要明确下一状态由旧状态计算，不能按“先把 a 改成 b，再让 b 读新 a”的普通程序直觉解释。具体语言支持与编码规则以目标工具文档为准。[R04]

### 算术右移必须核查符号

不能仅看到 `>>>` 就认为符号位一定扩展。你必须检查左操作数是否 signed、拼接后是否失去符号、结果宽度是否改变。写出负数、零、最大正数和大移位量的独立测试。[R04]

### 可以仿真不等于可以综合

测试台中的时延和输出打印是测试机制，不应该被候选复制进 DUT 作为功能实现。与此同时，也不能机械地说所有 `initial` 都不可综合：FPGA 初始化有受支持的用法。本包按自包含范围限制 I/O 构造，而不是把一个语法关键字当万能判定。[R04]

## 4. 建议练习序列

先写 mux/decoder/priority encoder，再写带同步/异步复位的计数器与移位寄存器，然后写检测重叠序列的 FSM，最后写参数化 FIFO、握手流水线和简单存储模块。

每个练习都保留三份东西：自然语言契约、DUT、独立测试台。不要让测试台直接照抄 DUT 的算法，否则二者容易共享同一错误。对小状态空间尽量穷举；对较大空间使用定向边界加固定种子的随机测试。

推荐的故障注入包括：复位极性反了、同步写成异步、计数器加二、漏写 enable hold、输出延迟一拍、位宽少一位、FIFO 空/满边界错误、参数 N=1 产生零宽向量。通过“故意写错还能否被抓住”来验证测试台的价值。

## 5. 分阶段里程碑（按能力推进，不是官方日期）

| 阶段 | 产物 | 达标条件 |
|---|---|---|
| 第 1 阶段 | 5—10 个小模块和自检测试台 | 能解释输入、状态、输出和失败周期 |
| 第 2 阶段 | 不含 LLM 的命令行验证器 | 真实 2025.2 下能区分编译错/仿真错/综合错 |
| 第 3 阶段 | 单模型裸跑 | 离线、可复現、保留原题和原始响应 |
| 第 4 阶段 | 一次诊断修复 | 编译错误和计数器功能错误可以自动修复 |
| 第 5 阶段 | 技能 + 消融 | 在冻结留出集上证明增益不是只对训练样例有效 |
| 第 6 阶段 | 官方容器演练 | 网络关闭、资源受限、版本冻结、可一键复現 |

熟练者可以压缩这些阶段；新手可按约 4—6 周规划，但不要把这个估计视为完成时间承诺。首次 ROCm/EDA 迁移可能成为主要耗时，应尽早做，不要拖到最后。

## 6. 哪些内容暂时不用深钻

第一版无需从零推导 Transformer 反向传播、CUDA/HIP kernel 优化、分布式训练、多模态架构或复杂强化学习。真正需要的模型知识是：如何固定模型、正确打包输入、管理上下文、识别截断、控制采样、记录显存和耗时。

也不要求先做一个 GUI。能查清一次失败的命令、源文件、日志、返回码和时限，比复杂面板更有帮助。

## 7. 你与 AI 的分工

你决定规范、合法测试资产和实验目标；AI 协助实现模块、写测试初稿、分析日志、提出修复假设；编译器、仿真器、综合器提供外部证据。你负责审核测试本身、比较实际指标、决定保留哪项修改。

每次让 AI 修改一个明确模块，并要求提供失败复现、补丁、测试、运行命令与未验证项。不要同时请求“把整个系统全部优化”，否则很难归因某个收益或回归。
