# 04 · 代码结构、任务接口和运行产物

## 1. 文件职责

| 文件 | 职责 |
|---|---|
| `agent/common.py` | 任务/配置校验、预算、阶段结果、哈希和原子 JSON |
| `agent/llm.py` | 本地 HTTP 单次请求、上下文保护、响应提取、mock |
| `agent/knowledge.py` | 只读 BM25 技能检索 |
| `agent/rtlcheck.py` | 自包含/模块结构/测试隔离检查，不是完整 parser |
| `agent/process.py` | 无 shell 的子进程、超时、日志上限、进程组终止 |
| `agent/eda.py` | xvlog/xelab/xsim/Vivado 适配、分阶段证据、mock |
| `agent/engine.py` | 基线和智能体的独立流程、修复、回退和早停 |
| `agent/cli.py` | 单题入口、配置快照、共同预算、输出目录 |
| `scripts/synth.tcl` | 固定综合流程，器件与约束由可信适配层传入 |
| `scripts/evaluate_submission.py` | 不反馈给生成器的外部评估，适用于基线产物 |
| `scripts/metrics.py` | 开发用 pass@k 统计，拒绝 mock 与重复样本 |
| `scripts/make_task.py` | 把明确给出的原题/测试文件转成开发任务格式 |
| `scripts/doctor.py` / `scripts/freeze.py` | 环境诊断与不可变文件清单 |

## 2. 任务 JSON：这是开发接口，不是已知官方接口

```json
{
  "schema_version": 1,
  "task_id": "my_counter",
  "track": "rtl",
  "prompt_file": "prompt.txt",
  "top": "top_module",
  "clock_ports": ["clk"],
  "testbench_files": ["tb.sv"],
  "tb_top": "tb_counter",
  "success_pattern": "^AGENT_TEST_PASS\\s*$",
  "fixture": false
}
```

`prompt.txt` 必须包含完整原题以及实际已提供的接口描述。基线直接发送这个文件的原文，不能为降低基线而删掉端口、条件或例子。`top` 与 `clock_ports` 是工具适配信息，必须由输入契约可靠获得；正式任务若没有这些字段，需要增加适配器，而不是靠正则猜测全部 HDL 语义。

测试文件只由固定工具读取，其内容不会直接塞入模型；必要的错误摘要可能包含期望/实际值等合法反馈。不能把官方不可见测试或参考实现偷偷加入模型上下文。公开开发数据的参考实现只用于建立合法的独立判定资产，不作为逐题检索答案。

没有测试台时，省略 `tb_top` 和 `success_pattern`，把 `testbench_files` 设为 `[]`。程序会编译/展开 DUT 并综合，但保持 `simulation=unavailable`。

MVP 只支持单文件候选，可含多个自包含 helper module。测试文件路径必须在任务目录内，拒绝绝对路径、越界路径和越界 symlink；测试文件 basename 必须唯一。需要包含文件、数据文件、宏、parameter override、vendor IP 或多文件生成时，先扩展显式 manifest 和安全文件复制规则。不要简单把整个题库目录暴露给模型。

## 3. 成对运行和基线公平性

```bash
bash run.sh task/task.json /tmp/experiment-001 --config configs/local.json --seed 1000
bash run_baseline.sh task/task.json /tmp/baseline-only-001 --config configs/local.json --seed 1000
```

第一条在同一次运行中产出 baseline 与 agent；第二条仅运行 baseline，不进行 EDA preflight，也不加载技能。两者共用同一个客户端实现与生成参数。Markdown 代码块提取属于相同的运输层处理，不会自动补端口或修复语法。

裸跑失败时保留 `response.txt` 和错误，不悄悄增加 retry。模型服务仍会应用同一 chat template；不把模型所需的通用聊天模板误解成额外赛题技巧。

## 4. 真实命令链

```bash
xvlog --sv --work work design.sv tb/tb.sv
xelab -debug typical -s agent_snapshot work.tb_counter
xsim agent_snapshot -tclbatch sim.tcl
vivado -mode batch -notrace -nojournal -source synth.tcl
```

固定脚本按 AMD 2025.2 的分析/展开/仿真和综合接口组织。不同任务的库、宏和复杂接口仍需在真实环境验收。[R03][R04]

仿真通过不仅要求进程正常结束，还要求可信测试台给出正向成功标记，且没有指定失败标记。综合通过要求正常退出、固定脚本执行到成功标记并生成非空网表。前一阶段失败后不推进后续“正式等级”；无测试台时综合作为额外结构检查。

## 5. 输出目录

```text
experiment-001/
  manifest.json                  配置、种子、输入哈希
  preflight/                     工具版本检查
  baseline/
    request.json                 只有原题的请求
    response.txt                 原始输出
    design.sv                    可提取时保存
    result.json
  agent/
    candidates/000/
      request.json               原题/技能/反馈
      response.txt
      design.sv
      result.json
      work/                      各工具日志、综合报告、网表等
    candidates/001/...
    progress.json
    final/design.sv              最好候选
    result.json
  summary.json
```

`local_grade` 是本包的局部证据等级，不是赛事的分数。`official_pass` 始终为 null。正常退出码只代表流程形成产物，并不代表候选正确；批量脚本必须读取结果字段。

## 6. 保留最好候选与错误处理

较差的修改不会覆盖最好候选。完全重复的候选会早停。环境故障不触发反复重写代码。输入错误会记录 `fatal_error.json`；输出目录已存在则拒绝覆盖。每一次请求、代码和工具日志都在独立目录中，便于重放和差异比较。

原型用 `request.json` 留下实际发送消息，便于审计基线没有被人为削弱，及 agent 没有读入不允许的信息。不要把这些任务级日志回灌为评测窗口内自动增长的知识库。

## 7. 已知实现边界

HTTP 客户端只接受 loopback 地址，禁止代理与重定向，无自动网络重试。使用非流式请求；阶段 socket timeout 不能替代赛事侧的外层硬截止/资源沙箱，特别要验证客户端断开后后端计算是否及时取消。

`rtlcheck.py` 是轻量拒绝危险/不支持构造的规则，不是完整 SystemVerilog 解析器，也不是安全隔离边界；可能保守拒绝某些合法代码。真正的安全边界是只读输入、非特权容器、无外网、限制挂载和资源配额。需要支持新的语法时添加明确用例与测试。

测试台语义正确性、广泛任务适配、精确 tokenizer 预算、复杂日志解析和真实模型峰值显存均需进一步验证。官方 I/O/评分器尚不明确，接入时应优先修改任务与工具适配层，保持核心控制流和基线逻辑不变。
