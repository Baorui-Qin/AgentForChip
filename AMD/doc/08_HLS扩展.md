# 08 · HLS 分支：如何扩展，不把 C++ 直接当软件程序

## 1. 交付范围说明

本包的通用 agent 仅实现 RTL。`examples/hls_sum/` 是独立 HLS 学习与工具链验收例子，不是可直接评测全部 HLS-Eval 的智能体；主程序对 `track=hls` 明确拒绝，避免假支持。

HLS 的高层状态机可以复用，但规范抽取、代码格式、工具适配、错误分类、技能库和判定证据都要分开。不要只是把 prompt 中的 Verilog 换成 C++。

## 2. HLS 的基本原理

高层综合把 C/C++ 算法映射为硬件：分析控制/数据依赖，安排运算发生的时钟周期，把运算绑定到加法器/乘法器/存储端口等资源，并生成控制逻辑与接口。因此同一段数学等价 C++，可能产生不同的延迟、启动间隔和面积。[R05]

需要区别 latency（一次操作的延迟）和 II（相邻操作可启动的间隔）。流水化可以改善吞吐，但受数据相关、存储端口和资源约束。循环展开消耗更多硬件和存储带宽；`II=1` 不是贴上 pragma 就必然实现。

## 3. 必须先抽取的契约

顶层函数名与参数；精确位宽、signed、数组边界；数据输入输出次数；溢出/舍入行为；是否允许浮点误差；控制协议与 stream 顺序；是否含跨调用状态；时钟、延迟与 II 限制；可用头文件和目标器件。

`int`、`float` 与 `ap_uint<N>`、`ap_int<N>`、`ap_fixed` 的语义不能混用后凭“数学上差不多”判正确。循环上下界必须可综合；动态内存、递归、运行期无界循环等要依据工具支持与任务契约严格处理。[R05]

## 4. HLS 工具流程

截图的判定为可解析→可编译→可运行（全部测试）→可综合，并要求由 Vitis HLS 完成。AMD 2025.2 提供统一命令行：`vitis-run --mode hls --csim` 做 C 仿真，`v++ -c --mode hls` 做 HLS 综合；可额外运行 C/RTL co-simulation 检查生成 RTL 的一致性。[R05]

```bash
cd examples/hls_sum
bash run_hls.sh
```

脚本包含 C 仿真、HLS 综合和额外的 C/RTL 联合仿真。没有用本机 g++ 替代正式 Vitis HLS 判定。C 仿真过程中的解析/编译/运行通常由一个流程驱动，不能只凭单个退出码就假定所有分级信息已精确分离；正式适配器应根据赛事允许的阶段证据解析日志或结构化状态。

联合仿真有价值，但不要把它强加为当前截图明确要求的附加评分层。官方若只判定某一级，仍按官方口径报告；额外检查单独标注。

## 5. 学习例子：16 个 8-bit 无符号数求和

最大和为 `16 × 255 = 4080`，12 位无符号数可表示，故例子使用 `ap_uint<12>` 累加器与输出。测试覆盖全零、全 255 和多组确定性输入。此例用来熟悉精确位宽与完整工具链，不刻意追求最小 II 或面积。

工具配置固定目标 `xczu3eg-sbva484-1-e`、时钟 5 ns。代码本次没有在真实 Vitis HLS 执行，因此不要把示例作为已验证性能设计。

## 6. HLS 特有的修复规则

| 失败类型 | 诊断方向 |
|---|---|
| 类型/函数签名不匹配 | 顶层契约、声明、引用和返回值 |
| 只有边界值失败 | 中间位宽、溢出、截断、定点舍入 |
| C 仿真正确但 RTL 联合仿真错误 | 状态、接口握手、未初始化数据、未定义行为 |
| 综合不支持 | 动态分配、递归、不可界定循环、库函数 |
| 无法达到 II | 循环依赖、存储端口、运算资源、pipeline 边界 |
| 数据流死锁 | stream token 数、FIFO 深度、读写顺序、条件分支 |
| 资源急剧增加 | 不当 unroll/partition、过宽数据类型、复制存储 |

先保证功能，再调整结构和 directive。新增 pipeline 或重排循环必须在 C 仿真和必要的 RTL 联合仿真中验证，不能为了“更高性能”改变接口或输出序列。

## 7. 接入通用 agent 的步骤

定义独立 `HLSTask`：原题、top、设计源/头文件、公开测试资产、类型与接口约束。实现 `HLSBackend`：只调用固定 Vitis 命令，保存解析/编译/运行/综合的证据。实现 C++ 安全与文件白名单，不复用 Verilog 正则。增加位宽、数组、pipeline、unroll、dataflow、stream 等 HLS 技能。最后在 HLS-Eval 的开发集和冻结留出集验证。[R02][R05][R15]

HLS 和 RTL 应有独立日志分类与结果统计，但可以共用本地模型客户端、预算、哈希、基线机制和实验框架。模型选择也应分别实测，不假定 RTL 最优模型同时是 HLS 最优模型。
