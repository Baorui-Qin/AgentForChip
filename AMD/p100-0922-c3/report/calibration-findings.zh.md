# 校准排除项分析

本次预先固定的候选题池包含原 40 题和新增 80 题。其中原 38 题可运行，新增 70 题通过校准。正式清单保留原 38 题，并按预先固定的 SHA 顺序取新增通过项中的前 62 题；8 道通过项作为备用，不进入模型成绩。以下 12 项排除记录在 100 题分母之外，也不计为模型错误。[排除记录](../calibration-exclusions.json)、[完整选题与校准出处](../calibration-provenance.json)

## 不应统称为“题目不合法”

| 分类 | 题目 | 已确认现象 | 正确解读 |
|---|---|---|---|
| 公共接口解析范围不足，5 题 | Prob080、Prob108、Prob062、Prob123、Prob132 | 前两题的端口列表带尾逗号；后三题直接给出待修复的模块代码，没有解析器要求的项目符号端口列表 | 属于当前 Host 解析器覆盖不足，不等于题目或 RTL 本身非法 |
| 正例失配，1 题 | Prob031_dff | 参考转接正例也产生 120/121 失配 | 评测链尚未校准，不能把失败归给生成模型；本次未修改或强行纳入 |
| 所选负例实际上正确，1 题 | Prob002_m2014_q4i | 公共规范要求恒 0；Host 的全 0“负例”同样得到 0/100 失配 | 负例设计不适合该题，不是模型能力或仿真器错误 |
| 参考 X 值使负例失效，1 题 | Prob053_m2014_q4d | 错误的恒 0 输出仍得到 0/100 失配 | 此配置下的负例辨错能力不足，需先修复校准或评测器，不能据 PASS 宣称正确 |
| TB 自身 TIMEOUT，2 题 | Prob141_count_clock、Prob082_lfsr32 | 正例虽为 0/199999 失配，但日志明确输出 TIMEOUT，未形成有效完成证据 | 不是本机 30 秒 wall-time 超时；XSim 约 4 秒正常退出。不能只看 0 失配放行 |
| 测试台端口不匹配，1 题 | Prob099_m2014_q6c | 展开错误 VRFC 10-3180，TB 找不到 Y2、Y4 端口 | 属于评测器接口兼容问题，不能要求模型靠修改受信任 TB 来通过 |
| 尚未人工审查兼容性，1 题 | Prob156_review2015_fancytimer | 冻结元数据为 MULTIPLE_MATCH / NEEDS_MANUAL_COMPAT_REVIEW | 保留严格审查要求，不自动扩大兼容变换规则 |

接口解析器只接受特定格式的项目符号声明，这解释了上述五项排除，但本次没有在看到测试结果后扩展解析范围或更换正式题单。[冻结解析器](../source-snapshot/rtl-tools/src/phase1/p10-dataset.ts)

## Prob053 的关键证据

公共规范是一个无复位的 XOR 反馈触发器，并非恒 0 功能。参考实现虽然把输出初值设为 0，但刺激输入初始为 X，首次时钟沿才用非阻塞赋值更新输入。原始 VCD 显示参考输出在时间 5 从 0 变为 X；恒 0 DUT 保持 0，测试台比较表达式却把参考中的 X 当成不约束位。因此这个负例通过不能证明评测器能区分正确与错误实现。这里的解释由源码和实际波形共同支持，不是从 PASS 标签倒推的猜测。[参考实现](D:/AMD/verilog-eval/dataset_spec-to-rtl/Prob053_m2014_q4d_ref.sv)、[测试台](D:/AMD/verilog-eval/dataset_spec-to-rtl/Prob053_m2014_q4d_test.sv)、[负例原始波形](D:/AMD/phase1-validation/p10-calibration-100-20260922-v1/group-1/preflight-eda/run-4alt5j/build/wave.vcd)

## 执行记录

校准全程没有模型调用。第二个工作进程在 Prob156 触发严格兼容性拒绝后停止；其已完成的 30 对正负例结果原样保留，新冻结的续跑配置复用这些完整记录并完成剩余项目。原失败日志、续跑输入哈希和最终结果均在校准出处清单中。没有把校准候选当作模型答案，也没有用模型成绩决定选题。

这些排除还意味着：最终 100 题成绩描述的是当前 Host 支持并完成校准的开发子集，不应外推为完整 156 题数据集上的准确率。
