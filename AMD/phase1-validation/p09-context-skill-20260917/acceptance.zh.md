# P09 128K 上下文与技能排查

## 结论

项目示例与新部署配置采用 131072 Token（128K）上下文、8192 输出预留、1024 安全余量，完整请求输入预算为 121856。提供方声明的窗口仍可进一步收紧它。旧配置和旧实验未改写。

官方 Rust 计量器离线验证包含 system、五个工具 schema、assistant 工具调用、工具返回及必要推理回传的完整请求：121856 输入 Token 接受，121857 拒绝；相同大请求在原 16K 项目窗口拒绝。该测试 API 派发为 0，不是服务端 128K 压力测试。此前输出截断与输入窗口不足是不同问题，本次没有宣称历史截断由上下文不足造成。

## 校准阻塞

历史 rising_edge/C 在模型请求为 0 时校准失败，根因是 Vivado 临时子目录消失引发实时扫描错误，不是模型无法调用 Skill。现有 Host 的 ENOENT 定向修复保持其他文件错误严格失败。本次同题 C 组在 128K 配置下完成真实正例校准、初始错误 FAIL、模型 edit_dut、verify_rtl 和四阶段 PASS，用了 2 次 API、1 次接受修复。单次复验成功不保证消除所有未来 EDA 环境故障。

## 模型能否调用 Skill

历史自主轨迹中未观察到 retrieve_skill，但 C 组上下文已自动注入适用规则，因此不调用不等于不可调用。本次三条技能均收到真实模型的原生 retrieve_skill 调用，Host 使用与生产流程相同的检索函数返回了对应规则。它们是明确要求检索的诊断探针，不冒充模型自主选择检索。

| 技能 | 原生检索并返回规则 | 后续往返 |
| --- | --- | --- |
| rtl.syntax_structure | PASS | PASS |
| rtl.sequential_specification | PASS | TRANSPORT |
| rtl.conditional_dependencies | PASS | PASS |

时序技能的后续请求遭遇零内容 TRANSPORT 错误；该请求 usage 为 null，没有重抽样或将其标为完成。这不否定已经收到的 retrieve_skill 调用，也不证明模型已接收完该次工具返回。诊断驱动另有一次派发前的目录/退出接口错误，API 为 0，原失败保留，校准没有重复运行。

## 技能自身检查与修复

三条规则的内容哈希、15 个引用验证文件及保存的真实 EDA 适用正反例均复核通过；这些正反例是历史真实证据的重新检查，不是本轮新的 EDA 运行。未发现规则内容损坏、引用篡改或这些适用性案例失效。规则仍是诊断指导，不是可执行修复程序，也未证明带来因果收益；历史 Skill Selector 修改差异仍无法从保留证据恢复。

已实施的代码修复：C 组在 EDA 校准前验证技能包结构、唯一 ID、规则哈希及证据文件；缺失、格式错误或变化统一返回 SKILL_EVIDENCE_INVALID，不再混为通用模型失败。A/B 不读技能包。原生检索与提示注入统一只使用当前阻塞阶段，避免从已成功阶段或旧反馈选取不适用规则。三条规则正文及历史 validated 状态未改写。
