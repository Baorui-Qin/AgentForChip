# 本次 100 题测试口径

## 授权与记录

用户明确授权本次 100 题测试向 `https://api.deepseek.com` 发送题目、候选 RTL、技能提示、工具定义及诊断/波形摘要，并使用已配置凭据产生调用费用。授权不扩展到其他批次。凭据和请求头不进入归档。

完整记录指 Harness 实际收到的全部规范化流块、接口返回的 reasoning、正文和工具参数，以及 Host 工具结果、EDA 命令与日志。它不是 HTTP/SSE 原始抓包，也不包含未公开或未返回的内部思考。超时或截断时保留已收到的部分流，不能声称保存了服务端尚未发送的内容。

## 模型配置

模型为 `deepseek-flash`，正常生成和修复使用 high reasoning，强制动作恢复关闭 reasoning。配置中保留 `temperature=0`，但不能据此声称结果确定性：DeepSeek 官方文档说明 thinking 模式不应用 temperature。官方文档也要求携带工具的 thinking 请求保留所发送助手历史的 reasoning_content，缺失可能返回 HTTP 400。本次实现不伪造该字段，而是移除关闭思考的助手/工具历史，将真实 Host 工具结果保留在下一请求的事实核心中。[DeepSeek Thinking Mode，2026-09-22 核对](https://api-docs.deepseek.com/guides/thinking_mode/)

## 分母与配对

100 题均须经过正负例校准。原 38 道可运行题保留；其余按预先冻结的 SHA 顺序选取最早 62 道校准通过题。校准排除项与校准通过但未选入的备用项均单列，不用模型结果挑题。

每题重新生成一个共享初始候选。Baseline 只评分这个候选；Agent 从同一候选继续。没有合法初始候选的题目计入固定 100 题端到端分母，但不会进入 Agent 修复。通过数既报告固定 100 题口径，也报告实际完成初始对照的条件口径，不能只用后者代表总准确率。

本次与旧 40 题实验使用的新生成候选不相同，跨批次差异不能单独归因于 Host 修复。当前样本经过接口与评测器过滤，且保留部分旧题，不是从全部 156 题随机抽取的无条件总体样本。配对统计只用于描述本批结果。

## 校准续跑

首轮校准使用两个工作进程。第二个进程在读取 Prob156 的冻结资产时遇到 `NEEDS_MANUAL_COMPAT_REVIEW`，按原有严格加载器终止。原始失败日志保留。独立的续跑配置固定已完成校准文件，只复用完整正负例对；对冻结元数据中待人工审查的题目记录排除，其他未知加载失败仍会终止。不修改数据集、兼容转换规则或已完成结果，也不调用模型。

## 费用与限制

报告列出接口已返回的输入/输出 token 与缺失 usage 的请求数。没有读取账户账单，不把已知 token 合计当作完整费用或实际扣款证明。本次最多 1000 次物理派发，最多两个独立比较作业。`full_os_isolation_verified=false`，受限 RTL 策略和受管理子进程不等于完整操作系统隔离。
