Let's check the reset: "resets the state machine to a state equivalent to if the water level had been low for a long time (no sensors asserted, and all four outputs asserted)." This implies the state is the water level. The outputs are based on state. So if state is A, outputs all 1. If state is B, outputs fr0=1, fr1=1, fr2=0, and dfr? If water level had been B for a long time, previous level is B, so dfr should be 0. So in state B (steady), dfr=0. But when transitioning from A to B, before the clock edge, state is A, outputs all 1. At the clock edge, state becomes B, outputs change to fr0=1, fr1=1, fr2=0, dfr=? If dfr is a Moore output based on state B, it would be 0. But the spec says if sensor change indicates previous level was lower, flow rate increased by opening supplemental. So during the transition, dfr should be 1. If we use Moore, dfr would be 0 immediately after the clock edge, meaning no pulse. That seems wrong. Therefore, dfr must be a Mealy output or the state must encode the direction. But the reset condition says "state equivalent to if water level had been low for a long time (no sensors asserted, and all four outputs asserted)". That state has all four outputs asserted, meaning dfr=1. So state A has dfr=1 always. For other states, dfr is 1 only if rising. So if we use Moore, state B would have dfr=0. But then how to get dfr=1 during rising? We could have separate states for rising/falling? Or we can make dfr a combinational function of state and s. Let's look at common HDLBits solutions.
