# P09 输出预算配对实验

## 结论

本次 8 个新实验已完成。2,048 档通过 4/4，8,192 档通过 4/4；两档截断分别为 0/4 和 0/4。配对结果中，低档未通过而高档通过 0 个，反向结果 0 个。这里的“通过”指当前源码经 compile、elaborate、simulation、synthesis 四阶段 PASS，并与导出源码哈希绑定。

8,192 档共有 2 个响应的实际输出超过旧的 2,048 上限，已知单请求最大实际输出为 3077 Token。这能证明新增额度被实际使用，但不能证明所有题目都需要该额度，也不能把一次配对差异解释为统计显著收益。

## 实验设计

选取上一轮发生截断的全部 4 个“题目 × 组别”，在本轮分别运行 2,048 和 8,192 两个预算，各一个新样本，共 8 个独立修复实验。采用交替预算顺序，从相同冻结错误 DUT 出发，不续接旧的部分响应，不替换历史成绩，不因失败重抽样。

两档使用相同当前 Host、完整工具协议、任务、技能、模型别名、high 推理设置、超时与 EDA 参数。只改变单请求 max_tokens 和匹配的上下文输出预留，另用独立 sample 标识隔离记录。当前 Host 包含上一轮封存后修复的 Vivado 临时子目录扫描问题；该修复同时用于两档，因此本轮新 2,048 档才是配对对照，旧结果仅作背景。

## 用量与耗时

| 单请求预算 | 四阶段通过 | 截断 | API 派发 | 实际输出 Token | 模型耗时秒 | 活动耗时秒 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2048 | 4/4 | 0/4 | 8 | 7112 | 50.9 | 748.3 |
| 8192 | 4/4 | 0/4 | 9 | 10356 | 68.6 | 758.2 |

模型耗时包括该请求的准备和计量。活动耗时还包括正例校准、初始错误验证和修复后的 EDA；更多成功验证本身会增加 EDA 时间，不能把总耗时差都解释为生成速度差。未知 usage 保留 null；不把已知用量当作账单或费用保证。

## 上下文与边界

上下文项目上限保持 16,384，安全余量保持 1,024。2,048 档可用输入预算为 13,312，8,192 档为 7,168。本次两档观测到的最大完整请求输入分别为 2967、4617 Token；发生上下文裁剪的实验数分别为 0、0。计量包含工具 schema、必要的推理回传和工具调用/返回，不做文本长度估算替代。

60 秒请求超时、65,536 字节响应限制、事件大小限制和 EDA 配额都保持不变。输出上限增大并不取消这些限制。DeepSeek 官方另有模型输出上限，本次 8,192 低于其公布上限；项目仍采用更小的 16,384 上下文窗口。[模型限制](https://api-docs.deepseek.com/quick_start/pricing/)

官方说明 thinking 模式下 temperature 不生效，因此发送 0 不代表确定性采样；模型别名也不是不可变权重标识。[Thinking 模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)

## 结论范围

这是针对历史截断单元的小样本预算比较，存在按历史结果选样的限制，不能报告为五题全量 A/B/C 成绩、自然生成成功率或统计显著策略收益。工具接口限制不等于操作系统隔离，full_os_isolation_verified 仍为 false；全面时序收敛和 Prob038 兼容性不在本次签收范围。
