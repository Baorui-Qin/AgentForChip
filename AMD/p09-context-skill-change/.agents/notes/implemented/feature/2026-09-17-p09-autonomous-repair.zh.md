# Agent Note: 显式启用的 RTL 自主修复

Status: implemented

[English](2026-09-17-p09-autonomous-repair.md) | 中文

## 问题

纯文本候选生成加人工审批能证明修复组件可用，却不能证明模型主动验证自己的 DUT 修改并消费新工具反馈。修复上下文对照还需要共同的冻结错误起点、完整请求计量和独立证据，而不是混合生成质量与修复质量。

## 决策

[现有修复工作流](../../../../rtl-tools/src/phase1/repair-workflow.ts) 拥有显式启用的自动模式。它复用解析后的模型适配器和 VerificationRunner，不修改核心 agent loop（智能体循环）。人工审查模式仍为默认。自动状态使用 schema 1.7，不能原地重新解释或升级历史状态。

宿主公开固定的原生工具注册表。模型只能提交完整 DUT、请求当前修订验证、读取当前 RTL、请求确定性指导，或结束但不宣称 PASS。宿主每个响应只接受一个完整动作，将多动作响应整体拒绝。接受编辑后创建不可变修订、清除验证状态，并要求下一次编辑前先验证。只有新鲜且绑定的四阶段 PASS 才允许导出。

[动作调用器](../../../../rtl-tools/src/phase1/p09-action-call.ts) 通过现有适配器序列化最终提供方请求，并使用哈希固定的官方 Rust 转换、编码与分词组件计数。发送的请求就是已审计的请求。最近一对协议必需的 assistant/tool 消息包含提供方回放字段；事实历史不保存模型推理。缺少运行时证据会阻止派发。本地精确计数与提供方 usage 是两项独立观察。

永久单元 claim 和持久化共享派发预留在崩溃后仍然保留。交付不确定的派发不会自动重放。应用拥有有界的零内容传输重试，底层重试关闭。最终 manifest（元数据清单）在终态事件写入且日志关闭后生成，排除自身，并在报告前重新核对文件集合完整性、大小与 SHA-256。

冻结缺陷实验使用独立的 A/B/C 状态和输出。skill（技能）晋升由宿主依据证据决定，不属于模型权限。显式预验收模式可在非主对照夹具上提供一条有哈希的草案；普通 C 请求只看到已验证条目。正式题目答案源码不进入指导内容。[P09 参考文档](../../../../rtl-tools/phase1/p09/README.zh.md) 拥有部署配置与限制说明。

C 组技能包在 EDA 校准前检查，避免缺失证据消耗校准工作或被误归为模型失败。技能包解析、内容哈希与证据文件共用明确的 `SKILL_EVIDENCE_INVALID` 结果。提示注入与原生检索都从当前阻塞阶段选择；已成功阶段的诊断与旧观察不能作为指导依据。A/B 仍不访问技能文件。更大的配置窗口继续使用完整请求计量与提供方上限，而不是估算容量。

## 考虑过的替代方案

**独立 agent 框架或 HTTP 客户端。** 不采用，因为现有工作流、适配器和验证服务已经拥有所需生命周期与证据。第二套实现会重复传输、取消和验证语义。

**在自动实验中保留逐候选审批。** 人工审查仍是默认模式，但无法检验所需的自主工具循环。显式启用的模式接受已明确承认的开发机风险，不把工具限制称为操作系统沙箱。

**估算 Token 或手写提供方模板。** 不采用，因为完整工具消息与回放字段会改变实际输入大小。缺少固定版本的官方计数器是阻塞失败，不是允许估算的理由。

**续跑交付不确定的请求或挑选有利重复样本。** 不采用，因为两者都会改变有效抽样预算。永久 claim、不可返还的派发预留和固定分母报告保留未完成与失败观察。

## 影响

模型可见接口不能选择路径、命令、Tcl 或测试资产。保守源码检查刻意拒绝部分本来合法的 SystemVerilog。现有进程回收、环境变量名称清除、资产哈希和配额能限制暴露面，但不提供完整操作系统隔离。每份自动记录都保留 `full_os_isolation_verified=false`。

实时配额扫描允许遍历期间临时子目录消失导致的 ENOENT。运行根目录缺失或其他文件系统错误仍会中止。可信资产检查和终态清单审计保持严格；保留证据消失不会被当作无害的实时目录竞争。

确定性测试覆盖修订新鲜度、未验证结束、部分/多动作响应、重试计量、硬链接运行时拒绝、跨进程 claim 及终态清单。真实 API/EDA 证据属于独立实验批次，不能从这些测试推断。一次修复成功不证明多轮循环或上下文策略收益。固定缺陷成功不证明自然生成准确率、实现时序收敛、Prob038 兼容性或统计显著收益。
